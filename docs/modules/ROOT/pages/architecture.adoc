= Architecture

Attaching follows a Symfony-oriented structure based on the default `App\\` namespace.

== Current structure

The current repository exposes these main technical surfaces:

* HTTP controllers under `src/Controller/Http/Attachment/`
* application services under role branches such as `src/Service/Linking/Attachment/`, `src/Service/Query/Attachment/`, `src/Service/Storage/Attachment/`, `src/Service/Transfer/Attachment/`, and `src/Service/Validation/Attachment/`
* service contracts under the corresponding `src/ServiceInterface/.../Attachment/` role branches
* transport DTOs under `src/DTO/Input/Attachment/` and `src/DTO/Output/Attachment/`, with canonical `*DTO` type suffixes
* persistence entities under `src/Entity/Persistence/Attachment/`
* Doctrine repositories under `src/Repository/Doctrine/Attachment/`
* maintenance and runtime commands under `src/Command/Maintenance/Attachment/` and `src/Command/Runtime/Attachment/`
* authorization voter under `src/Voter/Authorization/Attachment/`

== Boundary notes

This repository intentionally stays Symfony-oriented:

* `App\\` namespace only
* no `/src/Domain/`
* no ports-and-adapters drift

The component currently acts as an attachment lifecycle brick with upload, attach, detach, list, download, delete, and orphan cleanup responsibilities.
