= Architecture

Attaching follows a Symfony-oriented structure based on the default `App\\` namespace.

== Current structure

The current repository exposes these main technical surfaces:

* HTTP controllers under `src/Controller/Http/Attachment/`
* application services under typed `src/Service/*/Attachment/` roots
* service contracts under mirrored `src/ServiceInterface/*/Attachment/` roots
* persistence entities under `src/Entity/Attachment/`
* repositories under typed `src/Repository/*/Attachment/` roots
* local storage implementation under `src/Service/Storage/Attachment/`
* maintenance commands under `src/Command/Maintenance/Attachment/`
* runtime/bootstrap commands under `src/Command/Runtime/Attachment/`
* standalone Symfony bootstrap under `app/`, `bin/`, and `config/` alongside the reusable bundle surface

== Boundary notes

This repository intentionally stays Symfony-oriented:

* `App\\` namespace only
* no `/src/Domain/`
* no ports-and-adapters drift

The component currently acts as an attachment lifecycle brick with upload, attach, detach, list, download, delete, and orphan cleanup responsibilities.
